## 介绍

写 Linux 定时任务时，最头疼的就是 Cron 表达式：`0 9 * * 1-5` 到底是每周一到周五早上九点，还是包含周六？写错了轻则任务不跑，重则半夜三更定时弹窗。

OpenHub 的 Crontab 计算服务就是解决这个问题的——把表达式扔给它，立刻告诉你接下来（或之前）具体的执行时间点，一目了然。

## 可以怎么用

- **推算下次执行**：验证表达式是否符合预期，比如 `*/5 * * * *` 是不是每 5 分钟一次。
- **反查上次执行**：想知道某个任务上次在什么时间点跑过，切换到"之前"查询即可。
- **批量查看**：一次查多个时间点，方便安排资源或核对任务节奏。
- **自定义时间格式**：默认返回 `2026-08-19 21:00:00` 这样的格式，也可以换成自己习惯的写法。

## 快速体验

在浏览器打开下面的地址，就能看到效果（也可在线调试）：

```
https://hub.saintic.com/openservice/crontab?expression=0 9 * * 1-5&query_times=3
```

上面的链接会告诉你：工作日早上 9 点，接下来三次分别在什么时候。

几个参数说明：

| 参数 | 作用 |
| ---- | ---- |
| expression | Cron 表达式，如 `*/5 * * * *` |
| query_times | 查询次数（1-32），想看几次填几次 |
| query_type | `next` 查之后的，`prev` 查之前的 |
| format_time | 时间显示格式，可自定义 |

## 适合什么场景

- 写定时任务前验证表达式，避免低级错误
- 排查"任务为什么没在预期时间跑"，反查一下历史执行点
- 交接脚本时，快速向同事解释某个任务多久跑一次、什么时间跑
- 学习 Cron 语法，边试边理解五段式的含义

一句话总结：写 Cron 没把握时，先来这里算一下，心里就有数了。
